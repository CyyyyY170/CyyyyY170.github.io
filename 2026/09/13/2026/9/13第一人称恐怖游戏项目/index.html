2026.9.13第一人称恐怖游戏：走廊

《走廊》：UE5 纯蓝图循环恐怖游戏技术全景

第一人称恐怖游戏 Demo：玩家在一条 C 形走廊里一圈一圈地走，每穿过一次出口门，世界就换一个”版本”——而玩家难以察觉切换发生的瞬间。

本文是项目的技术全景复盘：架构如何演进到 v3、无缝传送的算法与落地、”版本切换”为什么可以完全无感、八个版本的内容系统如何组织、双结局如何从一通电话里长出来——以及支撑这一切的关卡设计铁律与踩坑记录。

技术栈：UE 5.8 · 纯蓝图 · 单持久关卡 · 无 AI 敌人 · 纯环境恐怖。

一、项目定位：核心体验本身就是一个技术命题

玩法：玩家在一条循环的走廊中行走，每圈走廊内容都会变化，异常逐渐升级，最终走向好结局或坏结局。

核心体验：玩家明知走廊在循环，但无法判断循环（版本切换）发生的精确位置。

这句话是整个项目所有技术决策的出发点。做”循环走廊”不难，难的是”循环不可感知”——如果传送瞬间画面跳一下、方向偏一度、光照变一档，玩家立刻学会”传送点在门后两米”，整个游戏的恐怖感当场破产。所以这不是一个”先做功能再打磨表现”的项目，而是先定下”无痕”这个验收标准，再反向推导架构的项目。

几个从第一天就锁死的体验决策，每一条都在给技术方案设限：

  • 无 HUD、无字幕、无圈数提示——玩家不知道自己第几圈，只能靠内容异常感知深度；
  • 纯环境恐怖——没有敌人，全场景只有两样东西可交互：出口门和 v6 的电话；

二、架构演进：为什么是”C 形走廊 + 传送闭环”

循环走廊在空间上怎么实现？三个方案摆在桌上：

方案 做法 问题
v2 物理闭环 走廊真的连成一个环，玩家走回起点 “走回起点”会被玩家察觉；双半区内容对半切换，切换位置暴露
v2 零位移切换 不动人、只切内容，玩家走到某触发点世界原地翻新 脚下/眼前的内容瞬间变化，穿帮风险最大
v3 传送闭环 C 形走廊不物理闭合，出门口后无缝传送回起点 传送本身的技术要求最高，但穿帮面最小、可控

最终选择 v3，理由藏在玩法里：出口门这个”假出口”本身就是 M3 结局翻转的位子——前 7 圈门后是循环，最后一圈门后是真正的结局。”出口就是入口，离开就是回来”的空间悖论，只有传送闭环能成立。

最终架构：

  • 走廊不物理闭合：C 形布局，闭环靠传送，没有回程段、没有中间墙。
  • 传送即版本切换：传送完成的同帧，整场内容从 vN 切到 vN+1，v1→v2→…→v8→v1，8 个版本 = 8 圈。
  • 切换瞬间玩家正站在短A——短A 永远中性，变化全部发生在玩家视野之外（拐角后面）。

无缝传送的完整算法拆解见项目内《技术博客-无缝传送.md》，这里只留骨架。

三、无缝传送：两次矩阵乘法的”零穿帮”

这个做法的妙处是位置、朝向、动量的连续性自动成立——玩家在入口盒里偏左 0.3m 面朝门走，落地时在出口盒里偏左 0.3m 面朝同样的走廊方向。速度同理：

动量方向跟着走廊朝向一起旋转，正在走、倒着走、侧着走全部成立（实测：倒走穿过传送盒，倒着出现在短A）。

三个容易被忽略的细节：

  1. 控制器朝向单独处理：K2_SetActorTransform 只挪 Pawn 本体，摄像机朝向由 Controller 的 ControlRotation 单独维护，必须取出来重映射再写回——否则落地后面向正确、视角还停在传送前，甩一下鼠标才”回正”；
  2. 用 bTeleport = true 而不是 SetActorLocation：Teleport 语义不扫掠、不触发碰撞响应，避免落地时和地面碰撞体互相推挤导致的抖动/卡住；
  3. 事件只绑 Entrance 盒，Exit 盒不绑任何事件：这天然消灭了”折返多切”——玩家落地后往回走、反复进出短A，都不会触发任何东西，每圈只推进一次。

四、版本切换：单关卡 + Tag 显隐，卡顿问题根本不存在

8 个版本的内容全部预生成在同一个持久关卡里，用 Actor Tag（Ver_1..Ver_8）分组。切换 = 一组 Actor 的显隐翻转。没有 Level Streaming、没有加载、没有卸载——“切换会不会卡”这个问题从架构上被删除了。

BP_LoopManager 是关卡里的单实例，逻辑简单到可以全文贴出：

三个设计选择值得写一笔：

  • 动态 Tag 查询："Ver_" Append ToString(Index) → String to Name，不缓存数组、不用 Map。版本组里增删任何物体都不需要改管理器代码——对单人开发来说，”改内容零代码”比”查询性能”重要得多；
  • OnLoopAdvanced(Version) 事件分发器是整个异常系统的挂载点：每个异常蓝图按版本号订阅，切换瞬间自动生效。M1 只埋钩子，M2 之后的内容全靠它驱动；
  • 切换顺序的坑在引脚上：Set CurrentVersion 必须接在藏旧 ForEach 的 Completed 引脚，接在循环体 then 上就会”组里有几个物体就跳几个版本”。

五、三个无痕条件：关卡设计就是技术约束

技术做对了位置/速度/视角，但传送瞬间玩家眼睛会看到什么，是关卡设计决定的。三条铁律，违反任何一条当场穿帮：

  1. 短A 绝对中性：切换瞬间玩家正站在短A里——短A 放任何版本内容，切换的那一刻它就会在玩家眼皮底下变。短A（出生点+传送落点）是全关卡唯一”不变的锚点”。
  2. 拐角干净区 5m：玩家站在短A，透过拐角1 能看到主走廊头段的一条”余光楔形”。主走廊前 5m 必须所有版本共用、无差异内容。
  3. 传送两侧环境一致：Entrance 盒周边（门后）与 Exit 盒周边（短A）的墙、地板、灯光一模一样，穿门瞬间画面构图不跳。

这三条推导出一系列硬性工程约束：

  • 灯光全部 Movable、不烘焙——版本切换是运行时显隐 Actor，烘焙光照（Lightmap/静态 GI）与显隐切换天然冲突；
  • 干净区灯光不挂 Tag、常亮；版本差异灯只放在干净区之后——切换瞬间玩家视野内的任何一盏灯都不能变；
  • 副走廊门端 2-3m 干净区（M2 新增）：出口门后 Entrance 盒周边必须与短A 一致，这是最容易犯的一条；
  • 后期处理全关卡统一：绝不在单个版本里放不同的 PostProcess Volume，那是切换穿帮源。

“无痕”从来不只是代码的事——它一半在蓝图里，一半在摆放规则里。

六、八个版本：静态内容 + 订阅式异常框架

8 圈的故事是一个家庭的记忆，也是恐怖的升级曲线：

版本 故事 内容落地
v1 一家人刚搬进新家 人字拼木地板 + 冷白灯组（基线）
v2 生活快乐，添置新物件 暖黄灯光、墙上挂画、台灯、床头柜
v3 家里有个爱坐摇椅的小孩 摇椅（蓝图）
v4 家人送小孩泰迪熊 泰迪熊
v5 大火吞噬一切 红光 + 洋娃娃（代指小孩） + 笑声（蓝图演出）
v6 想重新联系这个世界 旧电话响铃（分支点）
v7 和家人一起迷路了 旧照片
v8 / v8* 迷路的孩子遇见了你 结局演出

异常系统框架（BP_AnomalyBase）：M2 先搭骨架、M3 填事件。每个异常继承它：SubscribedVersion（Instance Editable）+ BeginPlay 里 Bind Event 到 LoopManager 的 OnLoopAdvanced，版本号匹配时调 ActivateAnomaly()（子类覆写）。订阅的是版本号而不是圈数——异常按版本固定编排，在它所属的版本每圈都会触发。

版本驱动蓝图群像（全部从资产逆向确认）：

  • BP_Door：E 键交互，Timeline + CurveFloat 驱动门板绕铰链 Yaw 旋转；玩家进短A 后延时自动关门 + 音效——门的开合动画天然遮蔽循环边界；
  • BP_RockingChair（v3）：订阅版本号，玩家进入触发盒 + 版本匹配时开始摇动，附摇椅音效；
  • BP_WallClock：版本驱动的座钟，ClockVersion + HandleVersionChanged，每个版本显示不同状态、伴随钟声；
  • BP_v5_change：火灾演出——红光（Ver_5red）+ 洋娃娃显隐 + 笑声，Delay 编排演出节奏；
  • BP_V6Phone：响铃 + 150cm 距离提示（WBP_PhonePrompt 弹出”Press E to answer”）+ E 接听 + Armed 状态位。

七、双结局：一通电话决定的两重命运

v6 的电话是整个游戏的支点，也是最轻量的”选择”设计：接听与否不影响版本推进（接不接都照常走 v7→v8/v8*），只决定最终结局——玩家甚至意识不到自己刚才做了一个选择：

结局 触发 含义
v8 坏结局 v6 接听了电话 孩子就此认识玩家，想把玩家留下陪他
v8 好结局* v6 未接听 孩子不认识玩家，转身找家人

结局演出由 BP_EndingManager 驱动：洋娃娃jump scare、门锁启动、结局 UI 淡入淡出（WBP_GoodEndScreen / WBP_BadEndScreen，UMG 动画 + MovieScene 缓动）、字幕下方”按 P 重新开始”。

八、表现层：灯光、后期、音频的”无痕”协同

  • 灯光：常亮基础灯（短A + 干净区）+ 每版本 3 盏主灯（改色温）+ 2-4 盏氛围增量灯。不做”8 套全量灯组”——64+ 盏 Movable 灯性能直接崩。渲染配置上关闭动态 GI/反射（r.DynamicGlobalIlluminationMethod=0、r.ReflectionMethod=0），SM6 + 虚拟阴影贴图 + Substrate，氛围靠直射光 + 后期压出来；
  • 后期：Saturation 0.7-0.8 褪色、Vignette 0.4-0.6 边缘压迫、Film Grain 0.15-0.25 粗粝、微降曝光——全关卡统一，不破坏无痕；
  • 音频：环境底噪用 MetaSound 零外部资产合成——White Noise → Lowpass（200-400Hz）→ 音量 -30~-40dB，再叠一层 55Hz 极低音量正弦波。底噪全关卡共享、传送不切音频，这是”无断裂音”的保证。版本内容音效（电话/玩偶/小孩笑声）来自 SoundsOfHorror 等免费包。

九、单人开发方法论：这套项目怎么被做出来的

比起单个技术点，这个项目更值得记下来的是一套里程碑 + 验收清单的推进方式：

  • M1 骨架 → M2 版本内容 → 双结局 → M4 打磨，每个里程碑自带验收测试清单，逐项打勾才算完成；
  • M1 的 7 项验收里有两条是整个方案的地基：“走完整圈、开门、穿过传送盒：回到短A，画面零跳变” 和 “传送瞬间盯着屏幕：短A 内无任何可见变化”——验收的不是功能，是体验；
  • 第 5 条验收是 “倒走穿过传送盒：倒着出现在短A，动量连续”——用反直觉用例逼出”方向无关性”，这种测试设计值得单拎出来；
  • 单版本摆放后立即验证：临时把 MaxVersion 改成 2 快速测回卷、验收期把步速临时改 600 连走 8 圈——用配置开关换取测试效率；
  • 坑位日志：踩过的坑全部记录在案，新坑随时追加。下面挑最有价值的几条。

十、踩坑精选

# 坑 症状 解法
1 盒子红箭头朝向反了 180° 玩家落地头朝后、速度反向 Entrance/Exit 红箭头都朝玩家行进方向
2 BoxSize = 0 重叠事件永远不触发 在关卡实例上设置盒子尺寸
3 事件绑到 Exit 盒上 出生即触发，开局就传送 事件只绑 Entrance，Exit 不绑
4 Set CurrentVersion 接在循环体 then 上 组里有几个物体就跳几个版本 必须接在 ForEach 的 Completed 引脚
5 Tag 加在 Component Tags Get All Actors With Tag 查不到 只有 Actor 分类下的 Tags 才被匹配
6 干净区灯光挂了版本 Tag 切换瞬间玩家视野内明暗突变 干净区灯必须常亮、不挂 Tag
7 压扁 Cube 贴面 Z-fighting 污渍/血迹闪烁 留 0.005m+ 间隙
8 门后黑暗 Cube 挡住传送路径 传送被物理阻挡/触发不到 黑 Cube 放门洞内（墙里），不伸进 Entrance 触发区

十一、写在最后

这个项目目前走到双结局实现阶段。回头看，它最有意思的地方在于：所有技术决策都由一句”循环不可感知”倒推出来——传送闭环架构、同帧版本切换、三个无痕条件、Movable 灯、共享底噪、白点准星……没有一个是”别人都这么做”的默认选项，每一个都是体验要求的必然。

对单人开发者来说，这套”纯蓝图 + 单关卡 + 动态 Tag”的方案可能是一个可以复用的结论：当你的核心机制可以用”空间重映射 + 数据分组显隐”表达时，你就获得了零加载卡顿、零 C++ 依赖、随改随测的开发体验。抽掉游戏背景，传送盒是一个通用的 A→B 无缝传送工具；Tag 版本组是一个通用的”同场景多版本内容”框架（恐怖游戏异常、时间回溯、剧情分支都适用）。

技术栈：UE 5.8 · 纯蓝图（零 C++）· 单持久关卡。本文与《技术博客-无缝传送.md》配套：那篇讲透传送算法，这篇讲全项目。
